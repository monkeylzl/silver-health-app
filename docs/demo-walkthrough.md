# Silver Health Demo 演示路径（当前版本）

> 用途：
> - 给当前阶段的产品演示一个固定顺序；
> - 避免演示时跳来跳去；
> - 让“老人侧 + 家属侧”的价值链路更自然地展示出来。

---

## 一、演示前准备

### 1. 确保 API / Web 已启动
```bash
pnpm dev:api
pnpm dev:web
```

### 2. 确保 demo 数据已存在
如需重建：
```bash
pnpm seed:demo
```

### 3. 确保 Web 前端变量已正确配置
`apps/web/.env.local` 应包含：

```env
NEXT_PUBLIC_API_BASE_URL=http://localhost:3001
NEXT_PUBLIC_DEFAULT_ELDER_USER_ID=cmn5zm37f0000ijdo5tp2h0e0
```

---

## 二、推荐演示顺序

### Step 1：老人建档
页面：
- `/elder/profile`

讲解重点：
- 支持直接建档
- `userId` 可以留空
- 系统可自动创建 elder 用户
- 建档成功后可回填 userId

价值点：
- MVP 起点清晰
- 不依赖复杂前置流程

---

### Step 2：老人首页（今日任务）
页面：
- `/elder/home`

讲解重点：
- 展示今日任务列表
- 展示待完成 / 已完成统计
- 支持直接标记任务完成

价值点：
- 体现“老人今天该做什么”
- 是日常使用频率最高的核心页之一

---

### Step 3：健康指标录入
页面：
- `/elder/metrics`

讲解重点：
- 同页完成录入 + 查看
- 支持血压 / 血糖 / 体重三类指标
- 当前能看到 seeded 的真实数据记录

价值点：
- 体现健康管理产品的核心数据能力

---

### Step 4：用药提醒
页面：
- `/elder/medication`

讲解重点：
- 可新增提醒
- 可查看提醒列表
- 当前已能显示真实 seeded 提醒

价值点：
- 把健康记录延伸到长期提醒场景

---

### Step 5：家属看板
页面：
- `/family/dashboard`

讲解重点：
- 聚合任务、指标、用药提醒摘要
- 家属可以快速看到老人近况

价值点：
- 体现产品不是单人工具，而是“老人 + 家属”双角色协同

---

### Step 6：家属周报
页面：
- `/family/report`

讲解重点：
- 展示一周的任务/记录完成情况
- 展示摘要和建议

价值点：
- 强化家属侧“回顾 + 判断”的能力

---

### Step 7：家属绑定
页面：
- `/family/bind`

讲解重点：
- 可发起绑定申请
- 可查看已绑定关系

价值点：
- 把双角色关系闭环补齐

---

## 三、当前最适合强调的产品故事

建议当前演示不要把重点放在“功能很多”，而是放在这条故事线上：

1. 先为老人建档
2. 老人每天看任务、记指标、按提醒服药
3. 家属可以远程看到任务、指标、提醒和周报
4. 家属与老人通过绑定关系建立连接

一句话概括就是：

> **这是一个围绕“老人日常健康管理 + 家属协同查看”的 Web/H5 MVP。**

---

## 四、当前演示时建议避开的点

当前阶段尽量不要过度承诺这些：
- 原生 App 能力
- 小程序能力
- 推送通知真的已打通
- 复杂趋势图已经完善
- 家属绑定确认流转已经完成

这些还在后续阶段。

---

## 五、当前演示结尾建议

演示最后建议落在这三点：

1. **主链路已经成型**
   - 建档
   - 今日任务
   - 指标记录
   - 用药提醒
   - 家属查看

2. **本地真实联调已经跑通**
   - 不是纯 mock demo

3. **下一阶段重点是体验收口和远程数据库切换准备**
   - 不是再无限加页面

---

## 六、一句话结论

当前最适合的 demo 路径是：

> **建档 → 今日任务 → 指标录入 → 用药提醒 → 家属看板 → 家属周报 → 家属绑定**
