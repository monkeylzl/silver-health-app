# Silver Health 移动端应用产品化优化路线

## 优先级定义

- P0：部署体验版前必须完成。
- P1：第一轮真实试用前完成。
- P2：根据试用反馈推进。
- P3：进入正式商业化或原生客户端阶段。

## P0 发布前

### P0-1 生产安全变量

- Vercel 配置口令哈希、会话密钥、内部 API 密钥和服务端档案 ID。
- Railway 配置相同内部 API 密钥。
- 验证业务 API 无密钥返回 401，health 返回 200。
- GitHub 配置生产 smoke 所需 Secrets。

### P0-2 部署顺序与回滚演练

- 先 API、后 Web。
- 执行受保护 production smoke。
- 记录 Vercel/Railway deployment id。
- 验证可以回滚到上一部署。

### P0-3 真机安装

- Android Chrome 安装已完成。
- iPhone Safari 添加主屏幕及离线冷启动已完成。
- iPad 竖屏/横屏。
- 检查图标、安全区、独立窗口和离线提示。

### P0-4 敏感信息检查

- 搜索提交中是否出现数据库连接串、口令、Cookie 或内部密钥。
- 确认页面不展示 ID、API 地址和后端英文错误。

### P0-5 全局访问限流

- Vercel Firewall 对 `/api/session` 配置按 IP 的全局 rate limit。
- 确认限流发生在 Serverless Function 和 scrypt 之前。
- 应用内固定窗口限流继续保留为纵深防护。

## P1 第一轮试用

### P1-1 真实账号体系设计

- 老人与家人独立账号。
- 手机号或微信登录。
- 一位家人绑定多位老人。
- 邀请码/确认式绑定。
- API 按当前用户和关系授权，不再依赖固定老人 ID。

### P1-2 操作反馈

- 统一 toast 和保存成功状态。
- 防重复提交和请求超时。
- 弱网重试但不重复写健康记录。
- 删除提醒增加可撤销窗口。

### P1-3 数据趋势

- 指标类型切换与 7/30 日趋势。
- 血压高低压双曲线。
- 明确展示测量时间和录入角色。
- 趋势只做信息展示，不输出医疗诊断。

### P1-4 可观测性

- Web 错误追踪。
- API 结构化日志与 request id。
- Railway health 告警。
- Vercel 运行时错误和性能监控。

### P1-5 访问防护增强

- 增加失败次数告警、可控封禁和口令轮换流程。
- 根据试用规模评估 Redis/KV 的用户级限流与审计。

## P2 反馈驱动增强

### P2-1 家人任务配置

- 家人新增临时任务。
- 任务模板和重复规则。
- 到期、跳过与补做状态。
- 老人与家人操作记录。

### P2-2 用药执行记录

- 区分“提醒”与“已服药”。
- 漏服、补服、暂停疗程。
- 家人提醒但避免过度打扰。

### P2-3 周报升级

- 任务完成率、指标趋势、用药执行和记录完整度。
- 周报生成版本和历史对比。
- 导出或分享只读报告。

### P2-4 无障碍增强

- 字号模式。
- 更高对比度模式。
- 屏幕阅读器真机测试。
- 普通话语音播报可行性验证。

## P3 中长期

### P3-0 原生网络设置入口

- H5/PWA 保留网络重试和系统设置路径说明。
- 如需点击后直接打开 iOS/Android 网络设置，使用原生 App 或 Capacitor 壳提供平台级能力。
- 不在 PWA 中使用未公开、可能失效的 iOS 私有 URL Scheme。

### P3-1 通知与后台任务

- Web Push 可行性。
- 微信服务通知。
- iOS/Android 原生通知。
- 通知偏好、静默时段和频率控制。

### P3-2 多端客户端

- 微信小程序。
- React Native 或原生 App。
- 设备传感器与健康平台接入。
- PWA、微信和原生共享设计令牌与 API contract。

### P3-3 合规与商业化

- 隐私政策、用户协议和数据删除流程。
- 数据加密与审计。
- 医疗健康边界审查。
- 运营后台、组织账号和付费能力。

## 推进原则

1. 先验证老人和家人是否持续使用核心闭环，再扩展功能。
2. 不把固定体验账号直接演进成伪多用户系统。
3. 健康指标只做记录与趋势，不输出诊断性结论。
4. 新功能必须同时覆盖手机、Pad、无障碍和错误状态。
